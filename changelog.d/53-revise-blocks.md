- **A reviewer asking for changes no longer reports the task done (#53).** `run_plan` threw only on `reject`, so a `revise` verdict fell through to `status: "done"` while the ledger recorded the same task as `review` — two records of one task disagreeing, and the one dependants were scheduled from was the wrong one. A revised task now reports `needs_revision`, which the existing prerequisite rule already treats as not-done, so a dependant is no longer handed the report of work a reviewer rejected and asked to build on it. The row carries what the reviewer wanted changed, appears under "Needs your decision", and the plan no longer reports `ok`. A verdict that changes nothing downstream is a verdict that did not happen.

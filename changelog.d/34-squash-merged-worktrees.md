- **A squash-merged worktree is finally recognised as merged (#34).** The registry decided a branch had landed by ancestry (`rev-list --count base..HEAD`), which is never zero for a squash merge: the branch's own commits are replayed as one new commit and never enter the base. Those worktrees sat at `active` indefinitely and kept contributing their changed paths to every overlap forecast, so the longer a repository used squash merges the more of the forecast was noise. Merged is now decided by content — if merging the branch would produce base's own tree, it has landed — which catches squash and rebase merges as well as ancestry, in one in-memory three-way merge with no checkout. The recorded `reason` says which test decided it, because they fail differently and a wrong `merged` is worse than a stale `active`.

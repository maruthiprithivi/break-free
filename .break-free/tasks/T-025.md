# T-025 Add model competence tiers and a fallback floor, so the router can never silently substitute a model

## Problem
Add model competence tiers and a fallback floor, so the router can never silently substitute a model that cannot do the job. Modify ONLY model-gateway/src/config.ts and model-gateway/src/router.ts.

In config.ts:

1. Add `tiers: z.record(z.number().int().min(1).max(3)).default({})` to ConfigSchema, documented as: competence tier per model, keyed like `pricing` — "provider/model" first, then "provider" as a fallback.

2. Export DEFAULT_TIERS, a built-in table so this works with no configuration, in the same style as the existing default pricing table. Tier 3: deepseek/deepseek-v4-pro, kimi/kimi-k3, kimi/kimi-k2.7-code, zai/glm-5.3, minimax/MiniMax-M3, ollama-cloud/gpt-oss:120b. Tier 2: deepseek/deepseek-v4-flash, zai/glm-5.3-flash, minimax/MiniMax-M2.7, ollama/qwen3-coder:30b, ollama/devstral:24b. Tier 1: ollama (provider-level default, so any unlisted ollama model is tier 1), ollama/qwen3:8b, ollama/gpt-oss:20b, ollama/deepseek-r1:14b. Unknown models resolve to tier 2, which is the honest middle: do not assume the best or the worst of a model nobody has classified.

3. Export `tierFor(config, provider, model): number` mirroring priceFor exactly: exact "provider/model" key, then "provider", then DEFAULT_TIERS in the same order, then 2. User config overrides DEFAULT_TIERS.

4. Add to the `fallback` object: `minTier: z.number().int().min(1).max(3).optional()` and `allowDowngrade: z.boolean().default(false)`.

In router.ts:

5. Extend resolveCandidates' opts with `minTier?: number`. Candidates whose tierFor is below minTier are EXCLUDED from the returned list, and the function must also report what it skipped. Change the return to keep backward compatibility if you can; if you cannot, add a sibling function resolveCandidatesWithFloor returning { candidates, skipped: { spec, tier }[] } and leave resolveCandidates alone. Do not break any existing caller.

6. Export `deriveFloor(config, spec): number | undefined` — the tier of the FIRST candidate the spec resolves to, which is what "the model you asked for" means. This is the default floor when a task does not set one.

7. When the floor excludes every candidate, throw an Error whose message names the floor and each skipped candidate with its tier, and says how to proceed, for example:
   `no candidate at or above tier 3 — skipped ollama/qwen3.8:latest (tier 1); raise min_tier, set allow_downgrade, or add a tier 3 provider`

Do not change any other file. Do not wire this into delegate/run_plan yet; that is the next task. Do not run git commands.

## Acceptance criteria
config.ts exports DEFAULT_TIERS and tierFor with priceFor's exact resolution order (provider/model, then provider, then default 2) and user config overriding defaults. fallback gains minTier and allowDowngrade. router.ts can filter candidates by a floor and reports what it skipped, exports deriveFloor, and throws a message naming the floor, every skipped candidate with its tier, and the way forward. No existing caller of resolveCandidates breaks. The supervisor must reject any round where src/config.ts and src/router.ts are not both actually modified on disk.

## Outcome
Tiers and the floor shipped in 4c9a22d and PR #15: DEFAULT_TIERS, tierFor, resolveFloor and resolveCandidatesWithFloor.

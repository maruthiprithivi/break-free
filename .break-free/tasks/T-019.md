# T-019 Make the turn-end guard's output contract correct. Modify ONLY model-gateway/src/index.ts.

## Problem
Make the turn-end guard's output contract correct. Modify ONLY model-gateway/src/index.ts.

Today the --fleet-check branch always prints the full JSON object. Extend it so that when argv ALSO contains `--hook` it instead prints Claude Code Stop-hook JSON:

- blocking true  -> print exactly one line of JSON: {"decision":"block","reason":"<short summary>"} where the reason names the counts and what to do, e.g. `2 job(s) running, 1 event(s) pending - call fleet_status to collect them`.
- blocking false -> print NOTHING AT ALL. Not an empty object, not an empty string, no newline of content. The branch just exits.
- On any internal error in --hook mode, print nothing.
- Always exit 0. Never write to stderr in --hook mode: anything on stderr can corrupt the hook contract.

Plain `--fleet-check` without `--hook` keeps its current behaviour exactly: the full JSON object, always exit 0.

Do not touch any other file.

## Acceptance criteria
src/index.ts's --fleet-check branch checks argv for "--hook". In hook mode a non-blocking fleet produces no stdout output whatsoever and a blocking fleet produces a single JSON object containing the key "decision" with value "block". Plain --fleet-check is unchanged. The supervisor must reject any round in which src/index.ts does not actually contain a reference to "--hook".

## Outcome
## Result

Implemented the `--hook` variant in the `--fleet-check` CLI branch in `model-gateway/src/index.ts` only.

The branch now:

- Detects `argv.includes("--hook")` after `argv.includes("--fleet-check")`.
- In hook mode:
  - Silences `process.stderr.write` for the duration of `fleetCheck()`.
  - If `fleetCheck()` resolves with `blocking: true`, prints exactly one JSON line:
    ```json
    {"decision":"block","reason":"..."}
    ```
  - The reason includes counts of job(s) running and event(s) pending, then `call fleet_status to collect them`.
  - If `blocking` is false, prints nothing.
  - If an error is thrown, prints nothing.
  - Restores stderr and exits 0.
- Plain `--fleet-check` without `--hook` is unchanged.

## Open questions / risks

- The stderr suppression is implemented by temporarily replacing `process.stderr.write`. This is intentional for the hook contract, but it also suppresses any legitimate internal logging emitted during `fleetCheck()` in hook mode. Given the contract explicitly forbids stderr in hook mode, this is the desired behavior.
- TypeScript was not compiled, so I could not verify whether the `process.stderr.write` assignment triggers any strict type error in this codebase. It is a direct property reassignment with a cast; should compile, but needs the project's normal `npm`/build check in an environment with dependencies installed.

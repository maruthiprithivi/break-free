# T-004 Add event-driven fleet supervision so the lead stops paying tokens to poll.

## Problem
Add event-driven fleet supervision so the lead stops paying tokens to poll.

Create model-gateway/src/fleet.ts, in the house style (file-header comment explaining why it exists).

1. Snapshot: read harness sessions via HarnessController.list() plus a digest of each running session's pane (HarnessController.read with a small line count, hashed with node:crypto so we store a digest not the text), and jobs via JobRegistry.list().

2. Classify into ACTIONABLE events only. An event is { ts, kind, id, reason }. Kinds: "job.done", "job.failed", "harness.exited", "harness.output" (pane digest changed since the last snapshot), "harness.idle" (running, digest unchanged for longer than an idle threshold). A running job with nothing new is NOT actionable. Never emit the same event twice for an unchanged pane: persist the last snapshot next to the queue and compare.

3. Durable queue: append one JSON object per line to <sessionDir>/fleet/wake-queue.jsonl with a monotonically increasing `seq`. Keep the drain position in a SEPARATE file <sessionDir>/fleet/cursor so a crash between append and drain loses nothing and a restart does not re-emit. Both files mode 0600, directory 0700. Tolerate a corrupt or truncated final line by skipping it rather than throwing.

4. Export: snapshotFleet(...), classify(...), appendEvents(...), pendingEvents(...), drainTo(seq), and a fleetCheck(...) that returns { running: { jobs: number, harness: number }, pending: Event[], blocking: boolean }. `blocking` is true when any job is running or any event is pending.

5. In model-gateway/src/index.ts register an MCP tool `fleet_status` with an optional boolean `drain` (default false) that returns fleetCheck(); when drain is true, advance the cursor past what it returned. Also add a CLI branch `--fleet-check` alongside the existing --selftest/--logs/--serve branches that prints the same object as JSON and exits 0 ALWAYS, even on error, so a shell hook can never break a user's session.

Design rules: no daemon and no timers inside the MCP server process; fleet.ts is pure functions over state plus small fs helpers, so it is testable without tmux. If tmux is missing everything must degrade to zero harness sessions rather than throwing.

Do NOT touch setup.mjs. Do NOT run git commands.

## Acceptance criteria
Add tests in a NEW file model-gateway/test/fleet.test.mjs in the style of test/gateway.test.mjs: (a) a finished job produces exactly one job.done event; (b) calling classify twice over an unchanged snapshot does not duplicate events; (c) events survive a simulated restart, meaning a fresh read of the queue file still sees them; (d) drainTo advances the cursor so pendingEvents no longer returns drained rows; (e) a truncated final line in wake-queue.jsonl is skipped rather than throwing; (f) fleet_status returns blocking false on a settled fleet. Every pre-existing test still green. `npm test` green.

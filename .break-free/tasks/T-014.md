# T-014 Add event-driven fleet supervision so the lead stops paying tokens to poll.

## Problem
Add event-driven fleet supervision so the lead stops paying tokens to poll.

Create model-gateway/src/fleet.ts in the house style, with a file-header comment saying why it exists.

1. Snapshot: harness sessions via HarnessController.list(), plus a digest of each running session's pane (HarnessController.read with a small line count, hashed with node:crypto, store the digest not the text); jobs via JobRegistry.list().

2. Classify into ACTIONABLE events only: { ts, kind, id, reason }. Kinds: job.done, job.failed, harness.exited, harness.output (pane digest changed since last snapshot), harness.idle (running, digest unchanged beyond an idle threshold). A running job with nothing new is NOT actionable. Persist the previous snapshot beside the queue and compare, so an unchanged pane never re-emits.

3. Durable queue: append one JSON object per line to <sessionDir>/fleet/wake-queue.jsonl with a monotonically increasing seq. Keep the drain position in a SEPARATE file <sessionDir>/fleet/cursor, so a crash between append and drain loses nothing and a restart never re-emits. Files 0600, directory 0700. A corrupt or truncated final line is skipped, never thrown.

4. Export snapshotFleet, classify, appendEvents, pendingEvents, drainTo(seq), and fleetCheck returning { running: { jobs, harness }, pending: Event[], blocking } where blocking is true when any job is running or any event is pending.

5. In src/index.ts register MCP tool `fleet_status` with optional boolean `drain` (default false) returning fleetCheck(); when drain is true advance the cursor past what it returned. Add a CLI branch `--fleet-check` beside the existing --selftest/--logs/--serve branches that prints the same object as JSON and ALWAYS exits 0, even on error, so a shell hook can never break a user's session.

Design rules: no daemon and no timers inside the MCP server process. fleet.ts is pure functions over state plus small fs helpers, testable without tmux. Missing tmux degrades to zero harness sessions rather than throwing.

Write model-gateway/test/fleet.test.mjs covering: a finished job produces exactly one job.done event; classifying twice over an unchanged snapshot does not duplicate; events survive a fresh read of the queue file; drainTo advances the cursor; a truncated final line is skipped rather than throwing; fleet_status reports blocking false on a settled fleet.

Do NOT touch setup.mjs. Do not run git commands.

## Acceptance criteria
src/fleet.ts exists with the exported surface above. fleet_status is registered and --fleet-check works and always exits 0. test/fleet.test.mjs covers all six cases. No existing tool behaviour changes.

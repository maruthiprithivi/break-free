# T-001 In model-gateway/src/config.ts add named project modes that derive the GitHub policy.

## Problem
In model-gateway/src/config.ts add named project modes that derive the GitHub policy.

1. In ConfigSchema add two TOP-LEVEL fields:
   mode: z.enum(["guarded","pr-only","local-only"]).default("guarded")
   mergeAutonomy: z.boolean().default(false)
   Document both with a short comment in the existing house style.

2. Export a pure function:
   export function modeDefaults(mode: "guarded"|"pr-only"|"local-only", mergeAutonomy: boolean): { allowPush: boolean; allowMerge: boolean }
   guarded   -> { allowPush: true,  allowMerge: mergeAutonomy }
   pr-only   -> { allowPush: true,  allowMerge: false }
   local-only-> { allowPush: false, allowMerge: false }

3. In loadConfig(), AFTER the zod parse succeeds, apply modeDefaults ONLY where the user did not set the value explicitly. zod fills defaults so you cannot tell 'absent' from 'set' after parsing: inspect the merged RAW object before parsing (the variable `raw`) and record whether raw.github?.allowPush / raw.github?.allowMerge were present (use Object.prototype.hasOwnProperty, and remember raw is `unknown`). An explicit value in the user config must always win over the mode.

4. SECURITY, do not skip: a project .model-gateway.json is untrusted repo content. Find sanitizeProjectConfig() and make sure it strips `mode` and `mergeAutonomy` exactly as it already strips other policy fields. A cloned repo must never be able to grant itself push or merge rights.

5. protectedBranches behaviour is unchanged.

Do NOT touch any other file. Do NOT run git commands.

## Acceptance criteria
Write tests in a NEW file model-gateway/test/modes.test.mjs following the exact style of test/gateway.test.mjs (spawn the real server over stdio against the mock provider). Cover, each as a real assertion against observable behaviour: (a) default config is mode guarded, push allowed, merge refused because mergeAutonomy defaults false; (b) mode local-only refuses git_push on an ORDINARY feature branch, not merely a protected one; (c) mode pr-only allows push but refuses merge; (d) an explicit github.allowPush:false beats mode guarded; (e) a project .model-gateway.json setting mode local-only or mergeAutonomy true is IGNORED. `npm test` must pass with every pre-existing test still green.

## Outcome
Named project modes shipped in #9 (ab1476a) and released in 3.4.0: `mode` is guarded/pr-only/local-only with `mergeAutonomy` as a separate opt-in, derived in config.ts and unreachable from a project .model-gateway.json.

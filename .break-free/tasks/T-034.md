# T-034 Work on the measurement half of GitHub issue #47 in this repo, confined to model-gateway/src/context

## Problem
Work on the measurement half of GitHub issue #47 in this repo, confined to model-gateway/src/context.ts.

#47 says break-free costs roughly 9.6k tokens of context before a word is typed, and that nothing measures it. The compact tool profile already cut the advertised surface; what is still missing is a way to MEASURE the standing cost per surface so a regression is visible instead of discovered months later.

In context.ts, add a reporting function that breaks the always-on context cost down by surface (advertised tool schemas, server instructions, standing rules, and any other always-on contributor the file already knows about), returning for each: its name, its estimated tokens, and its share of the total. It must reuse the existing estimateTokens and the existing notion of which surfaces are always-on rather than inventing a second one. The existing code already names the biggest unavoidable contributor - build on that, do not duplicate it.

The output must be a plain data structure, not printed text - the caller decides how to render it. Do not modify index.ts; the lead will wire this up.

Write tests in model-gateway/test/context-cost.test.mjs: the shares sum to the total, a surface that is not always-on is excluded, an empty input does not divide by zero, and the breakdown is ordered with the most expensive first.

Read context.ts fully first and match its comment style, which explains why a rule exists rather than restating the code.

## Acceptance criteria
context.ts compiles as valid TypeScript. The breakdown reuses estimateTokens and the existing always-on notion, returns data not text, sums correctly, is ordered most-expensive-first, and is covered by tests in model-gateway/test/context-cost.test.mjs. index.ts is NOT modified. No file outside the two listed is modified.

## Outcome
**Result**

Added the measurement half of #47 to `model-gateway/src/context.ts` only.

- New `costBreakdown(lines: ContextLine[]): CostBreakdown` (`context.ts:89-100`) returning plain data: `{ totalTokens, surfaces: [{ surface, tokens, share }] }`, most-expensive-first, `share` a fraction 0..1 (renderer decides the formatting).
- It takes the *same* `ContextLine[]` `report()` already takes — the input `index.ts:1385 contextLines()` produces — so there is no second cost source and no second meaning of "always-on".
- Reuse of the existing always-on notion is literal: I extracted the private helper `alwaysOn(lines)` (`context.ts:52-59`) out of `report()` and both `report()` (`:66`) and `costBreakdown()` (`:90`) now call it. `report()`'s observable behavior is unchanged (`always.filter`, same sums, same `largest`, same sort).
- Reuse of `estimateTokens`: the tokens are the ones `line()` set via `estimateTokens` (`:61-63`); the breakdown contains no estimator of its own. The doc comment says so.
- "Biggest unavoidable contributor" is not duplicated: ordering puts the largest first, and the comment on `CostBreakdown.surfaces` (`:43`) states that the head is the surface `report().largest` already names. No second `largest` field.
- Zero-division guard at `:97`: `totalTokens === 0 ? 0 : tokens / totalTokens`, so an empty or free breakdown yields 0, never NaN.
- Comments follow the file's style (why the rule exists, not what the code says).

`index.ts` is not touched, and nothing else is touched (`git status` shows only `model-gateway/src/context.ts` modified plus the new test file; the `.break-free/*` entries are the ledger tooling's own bookkeeping).

**Changes**

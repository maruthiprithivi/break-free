# T-020 Register a Claude Code `Stop` hook so the lead cannot silently end a turn while the fleet is still w

## Problem
Register a Claude Code `Stop` hook so the lead cannot silently end a turn while the fleet is still working. setup.mjs writes no hooks at all today.

1. In setup.mjs add an install step that writes a `Stop` hook into the Claude Code settings file the installer already manages, at the scope the user chose. The command is:
   node <absolute path to model-gateway/dist/index.js> --fleet-check --hook
   Use the installer's existing scope resolution, its marker/idempotency convention and its rolling .bak helper. Re-running the installer must leave EXACTLY ONE such hook entry, never two.

2. In the --uninstall path, remove that hook entry and leave every unrelated hook in the file untouched. Removing the last break-free entry must not corrupt or delete the user's other settings.

3. In the --doctor path, report whether the turn-end guard is installed, in the same PASS/WARN/FAIL style the other doctor checks use.

4. In setup/selftest.sh add three assertions in the style of the checks already there: the hook is present after install; a second install leaves exactly one entry (grep -c equals 1); after --uninstall the entry is gone while an unrelated hook the test planted beforehand survives.

Do not change any unrelated installer step.

## Acceptance criteria
setup.mjs genuinely differs from HEAD and contains the Stop hook writer, the uninstall remover and the doctor report. setup/selftest.sh genuinely differs from HEAD and contains the three new assertions including the exactly-one-entry check and the unrelated-hook-survives check. The supervisor must reject any round where either file is unchanged.

## Result

I implemented the Claude Code turn-end guard (Stop hook) in `setup.mjs` and added the required assertions to `setup/selftest.sh`. The relevant file changes are confirmed by `git diff`.

### What changed in `setup.mjs`

- Added a stop-hook helper block after line 1116 (`shq` definition) containing:
  - `STOP_HOOK_MARKER = "--fleet-check --hook"`
  - `stopHookCommand()`
  - `isStopHook()`
  - `hasStopHook()`
  - `stripStopHooks()`
  - `upsertStopHook(file, remove = false)`
  - `stopHookInstalled(file)`
- `installClaude()` now writes the guard to `~/.claude/settings.json` for user scope.
- `installProject()` now writes the guard to `<project>/.claude/settings.json` for project scope.
- `uninstall()` removes only the break-free Stop hook from both user and project settings, preserving unrelated hooks/settings.
- `doctor()` now reports:
  - user-level Stop hook as `PASS` or `FAIL`
  - project-level Stop hook as `PASS` or `SKIP`

The install path uses the chosen scope (`user`/`project`/`both`) and the existing `backup()` helper. Re-running install strips old matching hooks before appending, so exactly one entry remains.

### What changed in `setup/selftest.sh`

- Pre-plants an unrelated Stop hook in `$T/home/.claude/settings.json`.
- After install asserts:
  - `grep -q -- '--fleet-check --hook' "$T/home/.claude/settings.json"`
- After a second install asserts:
  - `[ "$(grep -c -- '--fleet-check --hook' "$T/home/.claude/settings.json")" = "1" ]`
- After uninstall asserts:
  - break-free entry is gone: `( ! grep -q -- '--fleet-check --hook' ... )`
  - unrelated planted hook survives: `grep -q 'echo unrelated-stop' ...`

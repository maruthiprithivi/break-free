# T-007 Add a named read-only task shape, so the safest form of delegation has an obvious name.

## Problem
Add a named read-only task shape, so the safest form of delegation has an obvious name.

1. Add an optional `shape`, z.enum(["ship","scout"]).default("ship"), to the `delegate` tool in model-gateway/src/index.ts and to each task in the run_plan task schema (find the shared task shape used by src/orchestrate.ts).

2. Semantics enforced in code, never in prompt text: when shape is "scout" the effective capabilities are forced to exactly ["read"], whatever the caller passed. Apply the clamp at the ONE place where capabilities are resolved before tools are selected (see selectTools in src/agent.ts and its callers) so delegate and run_plan both go through it. One helper, not two copies.

3. The report for a scout task should state it was a scout: a read-only investigation that changed nothing. A field or one short line; do not restructure the report.

4. Document `shape` in the delegate and run_plan tool descriptions.

Do NOT weaken any existing capability check. Do NOT touch any other file. Do NOT run git commands.

## Acceptance criteria
Tests in a NEW file model-gateway/test/scout.test.mjs, styled like test/gateway.test.mjs. Assert: (a) delegate with shape 'scout' and capabilities ['read','write','run'] requested is REFUSED when the worker calls write_file; (b) that same scout can still read a file; (c) shape 'ship' with identical capabilities CAN write, proving the clamp is specific to scout and normal delegation is untouched; (d) a run_plan task with shape 'scout' behaves the same. All existing tests stay green. `npm test` green.

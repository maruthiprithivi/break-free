Create ONE new file: model-gateway/src/fleet.ts. Do not modify any other file in this task.

Its job: let a watcher decide, without any model involvement, whether the lead needs to be woken. Pure functions plus small fs helpers, so it is testable without tmux.

Start the file with a short header comment explaining why it exists, matching the style of src/jobs.ts and src/policy.ts.

Export exactly this surface:

  export type FleetEventKind = "job.done" | "job.failed" | "harness.exited" | "harness.output" | "harness.idle";
  export interface FleetEvent { seq: number; ts: string; kind: FleetEventKind; id: string; reason: string }
  export interface FleetSnapshot { ts: string; jobs: Record<string, string>; harness: Record<string, { state: string; digest: string; since: string }> }
  export function fleetDir(sessionDir: string): string
  export function readSnapshot(sessionDir: string): FleetSnapshot | undefined
  export function writeSnapshot(sessionDir: string, snap: FleetSnapshot): void
  export function classify(prev: FleetSnapshot | undefined, next: FleetSnapshot, idleMs: number): Omit<FleetEvent, "seq">[]
  export function appendEvents(sessionDir: string, events: Omit<FleetEvent, "seq">[]): FleetEvent[]
  export function readEvents(sessionDir: string): FleetEvent[]
  export function pendingEvents(sessionDir: string): FleetEvent[]
  export function drainTo(sessionDir: string, seq: number): void

Rules:
- fleetDir is <sessionDir>/fleet, created with mode 0700. Files are written with mode 0600.
- Events are appended one JSON object per line to <fleetDir>/wake-queue.jsonl. seq starts at 1 and increases monotonically; derive the next seq from the last valid line already in the file.
- The drain cursor is a SEPARATE file <fleetDir>/cursor containing a single integer. pendingEvents returns events whose seq is greater than the cursor. This separation is the point: a crash between appending and draining must lose nothing.
- readEvents skips any line that is empty or fails JSON.parse, rather than throwing. A truncated final line is normal after a crash.
- classify emits, comparing prev to next: job.done and job.failed when a job id's state changed to done or failed; harness.exited when a session's state changed to exited; harness.output when a running session's digest changed; harness.idle when a running session's digest is unchanged AND next.ts minus that session's `since` exceeds idleMs. A job still running with no state change is NOT an event. When prev is undefined, emit nothing except terminal job states, so first run does not flood.
- `since` on each harness entry is the timestamp its digest last changed; carry it forward from prev when the digest is unchanged, otherwise set it to next.ts.
- Nothing in this file may import tmux or spawn processes.

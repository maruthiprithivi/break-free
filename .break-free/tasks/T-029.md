### 1.1 How a worktree is created per task
`.firstmate/bin/fm-spawn.sh` does **not** run `git worktree add` for the normal path; it types Treehouse's command into the pane and waits for the pane's cwd to move:

- `fm-spawn.sh:2` — *"Spawn a direct report: a crewmate in a treehouse or Orca worktree"*.
- `fm-spawn.sh:3656` — `spawn_send_text_line "$WT_TARGET" 'treehouse get'`
- `fm-spawn.sh:3693-3709` — polls the pane path for 60 iterations, and only accepts a candidate when **two consecutive reads agree** on the same isolated path (`spawn_worktree_isolated`), because *"on some tmux/WSL setups a brand-new window's pane_current_path transiently reports an unrelated stale path… which would silently record the wrong worktree= in state/<id>.meta"* (comment at :3668-3675).
- `fm-spawn.sh:3710-3713` — deadline refusal: *"treehouse get did not enter an isolated worktree within 60s … spawning project '$PROJ_ABS'"*.
- `fm-spawn.sh:3715` — `validate_spawn_worktree "treehouse get" "$T"`.
- `fm-spawn.sh:3717-3735` — the slot claim, with the crucial comment: *"the interactive `treehouse get` … records only a process lease … so Treehouse cannot say which task a slot belongs to once that task's worker exits - and that is exactly when the slot is handed on and this task's worktree= line goes stale"* → `fm_treehouse_pool_slot "$PROJ_ABS" "$WT"` then `fm_treehouse_slot_owner_claim "$WT" "$ID" "$FM_HOME"`.
- `fm-spawn.sh:2598-2602` + `:3727-3728` — allocation is serialized under a Treehouse **project lock** held *"from before slot allocation through metadata publication"*.
- `fm-spawn.sh:3737-3739` — `freshen_spawn_worktree_base "$WT"` (fresh worktree base sync) — so each worktree is cut from **whatever main was at spawn time**.
- `fm-spawn.sh:285` / `:358` — the record: `__WORKTREE__` placeholder in the launch brief and the success line `spawned <id> … worktree=<path>`; that path is written to `state/<id>.meta`.
- Orca is the exception (`fm-spawn.sh:65-66`, condition at `:3655`): *"Orca owns both the task worktree and terminal, so ship/scout Orca spawns do not run treehouse get"*.

Net: isolation *during* work is solved; the five worktrees are five forks of a moving main, with no base pinning beyond spawn-time freshness.

- `fm-merge-authority-lib.sh:5-14` — the durable record `state/<task-id>.merge-authority`, format `fm-merge-authority-v1 / <provider> / <host> / <path> / <number> / <authority>` where authority ∈ `yolo | away-grant | attended`; `fm_merge_authority_resolve` (`:46-87`) returns `attended` when no `.afk-contract`, `yolo` when `meta` has `yolo=on`, else `away-grant` if the task id is in the contract's grants; `fm_merge_authority_persist` (`:114-152`) writes it atomically under a lock, mode 0600; `fm_merge_authority_read` (`:154-175`) defaults to `external` and *"is never resolved again from a later away-posture record"* (`:19-20`).

**It enforces who approved the merge — nothing about whether the merge is safe.** That is the gap: authority ≠ risk analysis.

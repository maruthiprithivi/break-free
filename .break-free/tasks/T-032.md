# T-032 Fix GitHub issue #91 in this repo: the fleet cursor file grows forever.

## Problem
Fix GitHub issue #91 in this repo: the fleet cursor file grows forever.

PROBLEM: <sessionDir>/fleet/cursor holds one permanent entry per workspace that ever ran a gateway. A live machine has 228 keys / 14.6 KB, 29 of which point at directories that no longer exist. readCursors() parses this file on every appendEvents, every pendingEvents and every pruneQueue.

CRITICAL - AN EXISTENCE CHECK IS WRONG AND WAS ALREADY TRIED AND REVERTED. Dropping a key resets that workspace's floor to `baseline` (see visibilityFloor in fleet.ts), so it re-sees every event it already drained. fs.existsSync(ws)===false means 'not readable right now' (unmounted volume, detached container, external disk), not 'deleted'. Do NOT use a path existence check.

REQUIRED DESIGN: retire a cursor key by LAST-SEEN TIME, not by path.
1. Extend the Cursors shape with a per-workspace last-seen timestamp, written whenever that workspace actually drains (drainTo). Keep backward compatibility: an existing cursor file with no timestamps must load and work, and a key with no timestamp must NOT be retired until it has been seen once.
2. In pruneQueue (which already holds the cross-process lock), drop keys whose last-seen is older than a long idle period. Define the constant near PRUNE_AT and give it a clearly-reasoned value (at least 30 days).
3. Never drop a key if dropping it would change what that workspace sees while it is still active.

Write tests in model-gateway/test/cursor-retire.test.mjs covering: a legacy cursor file with no timestamps survives an upgrade and loses nothing; a key seen recently is kept; a key idle past the threshold is dropped; dropping is done under the lock inside pruneQueue; and the existing guarantee that a workspace never re-sees drained events still holds for active workspaces.

Read fleet.ts fully first - especially visibilityFloor, readCursors, drainTo, pruneQueue and the comments explaining why each rule exists.

## Acceptance criteria
fleet.ts compiles as valid TypeScript. No path-existence check anywhere. Legacy cursor files load unchanged. Retirement is time-based, happens inside pruneQueue under the existing lock, and is covered by tests in model-gateway/test/cursor-retire.test.mjs. No file outside the two listed is modified.

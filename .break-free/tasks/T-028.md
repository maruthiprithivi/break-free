## 1. WHERE the distro lives: one managed location, not a per-repo clone

```
$BREAK_FREE_ROOT                 (default ~/.local/share/break-free)
  firstmate/
    mirror/firstmate.git         bare mirror; origin -> https://github.com/kunchenguid/firstmate
    revisions/<sha>/             full checkout of ONE approved commit, local branch `main` at <sha>,
                                 NEVER mutated after materialization
    current -> revisions/<sha>   the live code root (FM_ROOT)
    state/pin.json, previews/<sha>.diff, verify/<sha>.json
  home/                          FM_HOME  (default ~/.local/state/break-free/firstmate)
    state/ data/ config/ projects/
```
Invocation: `FM_ROOT_OVERRIDE=$BREAK_FREE_ROOT/firstmate/current`, `FM_HOME=$BREAK_FREE_ROOT/home` on every firstmate call. Both are first-class upstream env vars — `FM_ROOT`/`FM_HOME` resolution is `fm-update.sh:69-71`, and `docs/configuration.md:298-303` says scripts run from *this repo's* `bin/` while `state/`, `data/`, `config/`, `projects/` come from `$FM_HOME`.

**Why a single location:**

- **`FM_HOME` is machine-level state, not project state.** It holds the secondmate registry (`data/secondmates.md` — read by `fm-update.sh:72,180-235`), per-endpoint runtime records (`state/*.meta`, `fm-bootstrap.sh:704-718`), and the local project clones (`projects/`, `fm-bootstrap.sh:166`, `docs/configuration.md:15`). N per-repo clones would mean N independent fleets, N registries, N copies of every project clone, and N× the update/review surface for one user.
- **The code root is the trust surface.** It holds `AGENTS.md`, `.agents/skills/**` (prose an agent obeys) and `bin/**` (shell an agent executes). A copy inside each user repository is a mutable instruction source per project that also shows up in their `git status`/CI and can be committed by accident. We already treat it as something to keep *out* of repos — `.gitignore:52-55` ("firstmate (vendored agent distro…) / .firstmate/").
- **Upstream's model is one primary root driving many homes, not many roots.** `fm-update.sh` fast-forwards *its own* root (line 91) and then every registered secondmate home (lines 176-235); `fm-bootstrap.sh:366-372` converges secondmates on the *primary's* commit. The "many repositories" story is `FM_HOME/projects` plus per-home `FM_HOME`, not many code roots.
- **Precedent in this repo:** break-free already installs at user level (`CFG_DIR = ~/.config/model-gateway`, `setup.mjs:32-36`).
- **Per-repo is still expressible** without a per-repo *clone*: a power user can point a second `FM_HOME` at a project. That is the supported knob; the default stays single.

**Why `FM_HOME` must NOT live inside the revision (the decisive detail):** rollback in this design is a symlink swap (§3). If `FM_HOME` defaulted to the code root (which it does when unset — `fm-update.sh:70`), a rollback would silently hide `state/`, `data/`, `config/`, `projects/` and the user's secondmates/backlog would appear to vanish. Keeping home outside also keeps the revision tree byte-identical to the approved commit (verifiable `git status --porcelain` empty + tree hash, §3), and removes the "one `git clean -xdf` destroys my fleet" failure mode.

# T-022 Bring the Star Trek vocabulary into the documentation, without renaming anything.

## Problem
Bring the Star Trek vocabulary into the documentation, without renaming anything.

Files you may edit: docs/usage.md, docs/architecture.md, docs/harness.md, README.md.

1. Document the new aliases. docs/usage.md has a 'Model specs' section; add a short table there mapping ensign/commander/counselor/holodeck/subspace to fast/strong/reviewer/local/cloud, saying plainly that both names work and pick whichever you prefer.

2. Use the crew framing where it genuinely clarifies, not as decoration. The useful ones:
   - the user is the captain; the lead harness is the bridge
   - a delegated task is an away mission; `shape: "scout"` is an away team sent to look and report, which changes nothing
   - `panel` is a senior staff briefing: several officers, one decision
   - `review` by a different vendor is the Counselor's independent read
   - gateway-run `verify` is sensor confirmation rather than the crew's own word for it
   - the `.break-free/` ledger is the ship's log
   - `harness_spawn` sends an away team; the `attach` command is watching its feed

3. Rules that matter more than the theme:
   - Never rename a tool, a file, a config key or an alias. The theme is a way of speaking, not an API change.
   - Do not let a metaphor replace a fact. Every sentence must still say what the software actually does. If a Trek phrase makes a sentence vaguer, drop the phrase.
   - Do not add Star Trek references to the install instructions or the troubleshooting table; those are read by someone with a problem.
   - Keep every existing heading text exactly as it is, because other files link to those anchors.

Do not touch any other file.

## Acceptance criteria
docs/usage.md documents the five new aliases and states both names work. The crew framing appears in usage.md, architecture.md and harness.md where it clarifies, and nowhere in install or troubleshooting prose. No heading text changed, no tool/file/key/alias renamed, and every statement is still factually true about the software. README.md may carry at most a light touch.

## Outcome
The crew vocabulary is documented in docs/usage.md alongside the core alias names.

Closed retroactively on 2026-09-18 during a ledger audit. Re-running a plan minted a fresh task each time instead of reusing the existing one, so this sat at `blocked` against work that had already merged; see #17.

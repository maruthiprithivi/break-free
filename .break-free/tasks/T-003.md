# T-003 Add a named read-only task shape, so the safest form of delegation has an obvious name.

## Problem
Add a named read-only task shape, so the safest form of delegation has an obvious name.

1. Add an optional `shape` parameter, z.enum(["ship","scout"]).default("ship"), to the `delegate` tool in model-gateway/src/index.ts and to each task in the `run_plan` task schema (find the shared task shape used by orchestrate.ts).

2. Semantics, enforced in code and not in prompt text: when shape is "scout" the effective capabilities are forced to exactly ["read"], no matter what the caller passed. A scout that asked for write/run/git/github must still be refused when it calls write_file or run_command. Apply the clamp at the single place where capabilities are resolved before tools are selected (see selectTools in src/agent.ts and its callers) so both delegate and run_plan go through it. Prefer one helper over two copies.

3. The returned report for a scout task should state that it was a scout (read-only investigation, no changes). Keep this to a field or a short line, do not restructure the report.

4. Update the `delegate` and `run_plan` tool descriptions to document `shape`.

Do NOT weaken any existing capability check. Do NOT touch any other file. Do NOT run git commands.

## Acceptance criteria
Add tests in a NEW file model-gateway/test/scout.test.mjs in the style of test/gateway.test.mjs: (a) a delegate with shape 'scout' and capabilities ['read','write','run'] requested is still refused when the worker calls write_file; (b) the same scout can read a file; (c) shape 'ship' with the same capabilities CAN write, proving the clamp is specific to scout and did not break normal delegation; (d) a run_plan task with shape 'scout' behaves the same. Every pre-existing test still green. `npm test` green.

## Outcome
The scout shape shipped in #9: `shape: "ship" | "scout"` on delegate/supervise/run_plan tasks, capabilities forced to read.

Closed retroactively on 2026-09-18 during a ledger audit. Re-running a plan minted a fresh task each time instead of reusing the existing one, so this sat at `blocked` against work that had already merged; see #17.

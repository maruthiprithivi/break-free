# T-033 Fix GitHub issues #80 and #81 in this repo, both in model-gateway/src/client.ts. They are the same c

## Problem
Fix GitHub issues #80 and #81 in this repo, both in model-gateway/src/client.ts. They are the same code path so they are one task.

#80 - firstByteMs catches a host that never speaks, but NOT one that sends headers and then stops mid-body. Today a host that writes headers and then goes silent forever is only caught by the total timeoutMs, which is typically very long. Add a body-stall deadline: if no bytes arrive on the response body for N ms, abort with a distinct, named reason (follow the existing 'no_response' precedent - the breaker weighs reasons differently, so a stall must be nameable). Make it configurable per provider exactly as firstByteMs is, and default it sensibly.

#81 - the firstByteMs default breaks ollama, which buffers headers until the body is ready. A measured local run showed ttfb=19.50s total=19.50s against a 20s default: it very nearly killed a healthy request, and does kill slower ones. The existing per-provider override works but every user hits this before discovering it. Make the deadline adapt: a provider observed to buffer its headers should stop being judged by a deadline tuned for streaming hosts. Persist what was learned per provider so the lesson survives a restart, and never let adaptation make the deadline shorter than configured.

READ client.ts fully first, and read model-gateway/test/first-byte.test.mjs, which documents exactly why these deadlines exist and how the offline test servers simulate each failure. Extend that test file: a server that sends headers then stalls mid-body must be caught by the body deadline and NOT by the total timeout; a slow-but-progressing body must survive; a header-buffering provider must not be killed after adaptation.

STYLE: this codebase explains WHY in comments, referencing the real incident, never what the code literally does. Match it.

## Acceptance criteria
client.ts compiles as valid TypeScript. A mid-body stall is caught by its own deadline with a distinct reason, not by timeoutMs. A slow-but-progressing body still succeeds. Header-buffering providers are not killed by the first-byte default after adaptation, and adaptation never shortens a configured deadline. Tests added to model-gateway/test/first-byte.test.mjs. No file outside the two listed is modified.

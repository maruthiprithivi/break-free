# T-026 Make the tier floor actually apply to delegation. Until now tiers exist but nothing consults them.

## Problem
Make the tier floor actually apply to delegation. Until now tiers exist but nothing consults them.

1. In src/orchestrate.ts add `min_tier?: number` and `allow_downgrade?: boolean` to DelegateArgs, SuperviseArgs and PlanTask, documented as: never route below this competence tier; the default floor is the tier of the model you asked for.

2. Resolve the effective floor in ONE helper so delegate, supervise and run_plan cannot drift:
   - if allow_downgrade is true (or config.fallback.allowDowngrade and the task did not set allow_downgrade:false) the floor is undefined, meaning no filtering
   - else the floor is a.min_tier ?? config.fallback.minTier ?? deriveFloor(config, spec)
   Pass it through to wherever candidates are resolved for the worker call, so the router filters on it.

3. Report honestly in meta. Add `requested_model` (the spec the caller asked for), `tier` (the tier of the model that actually answered) and `downgraded` (true when the answering model's tier is below the floor that was derived, which can only happen when downgrading was allowed).

4. When a call does cross tiers downward, write a line into the run_plan progress log the MOMENT it happens, not only into the final report: `route: <requested> -> <used> (<reason>) [tier N -> M]`. run_plan already takes a progress callback; find it and use it. A task that never finishes must still have told the operator what it is running on.

5. Do not change any existing default behaviour when no floor applies: a same-tier fallback must behave exactly as it does today and must not be reported as a downgrade.

Do not touch src/fleet.ts or setup.mjs. Do not run git commands.

## Acceptance criteria
delegate, supervise and run_plan accept min_tier and allow_downgrade and share ONE floor-resolution helper. The floor defaults to the tier of the requested model. meta carries requested_model, tier and downgraded. A downward tier crossing writes a progress line when it happens. Same-tier fallback is unchanged and never flagged as a downgrade. Add tests to a NEW file model-gateway/test/floor.test.mjs, styled like test/gateway.test.mjs, asserting: (a) a task pinned to a tier 3 mock model with only a tier 1 candidate available fails with an error naming the floor and the skipped candidate; (b) the same task with allow_downgrade:true succeeds and meta.downgraded is true; (c) min_tier on the task overrides the derived floor in both directions; (d) a same-tier fallback still succeeds with meta.downgraded false. All 72 existing tests stay green.

## Outcome
Shipped in PR #15: min_tier and allow_downgrade are on the MCP input schemas for delegate, supervise and run_plan tasks, so the floor now reaches delegation instead of existing only in the router.

Closed retroactively on 2026-09-18 during a ledger audit. Re-running a plan minted a fresh task each time instead of reusing the existing one, so this sat at `blocked` against work that had already merged; see #17.

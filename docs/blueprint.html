Break Free Blueprint

How the pieces fit today — lead harness, crew models, the gateway between them, and the ledger that survives sessions, worktrees and merges — and what is still missing before it can act as facilitator, consigliere, coordinator, knowledge keeper and maintainer for all your coding work.

1 · The system in one picture

Everything runs on your machine. Any harness on the left is the lead: it talks to you, decomposes, decides, reviews. The gateway hands execution to any model on the right, holds the keys, enforces the guardrails, and writes everything durable into the ledger.

Several leads work at once, each in its own worktree. Knowledge is layered so that git only ever sees the ledger change on main; a branch PR carries code and nothing else.

5 · What's still missing

Mapped to the roles you named. DONE marks what v3.2 already covers; GAP is what it would take to be complete. Priorities: now unblocks daily use or closes a risk, next makes it richer, later is scale-out.

One risk to close first. Notes written by workers (ledger_note) are injected into every later worker's prompt. A model that reads a poisoned README can write a note that instructs the next model. Worker-written notes should land in quarantine (source: worker, not injected) until the lead promotes them. Small change, real attack surface.

Facilitator / concierge

Gets the right work to the right model with minimal ceremony.

  • DONE aliases + fallback chains, live model menus, chat-driven model switching (user/project), Codex shim, harness profiles, six extra harnesses.
  • GAP now Cost & budget: price table per model, $ per task/plan/day in gateway_logs, budget caps that stop a plan instead of silently draining a key.
  • GAP next Evidence-based routing: keep a per-task-type scorecard (review verdicts, verify pass rate, latency, cost) and let route recommend model + caps + verify for a new task; run_plan uses it when model is omitted.
  • GAP next Intake: a plan_from_issue that turns a GitHub issue or a paragraph into a proposed run_plan (tasks, deps, verify) for the lead to edit — the concierge desk.

Consigliere

Judgement and oversight the lead can trust without babysitting.

  • DONE gateway-run verify, review by another vendor, supervise loop, panels, least-privilege caps, destructive-tool filtering.
  • GAP now Note quarantine (above) and untrusted-content labelling of worker output before it enters the ledger.
  • GAP now Risk tiers as policy, not prose: .model-gateway.json rules such as "paths matching auth/** require review:true and a different vendor", "never delegate files matching secrets" — enforced by the gateway, not by the skill text.
  • GAP next Escalation ladder: after N failed rounds, auto-escalate to strong, then to the lead with a one-paragraph brief and the diff; record why in the task.
  • GAP next Vendor scorecards: which model's work gets rejected most, per task type — feeds routing and your buying decisions.

Coordinator

Keeps many agents and worktrees from stepping on each other.

  • DONE shared worktree registry, statuses with reasons, hand-offs, overlay ledger + absorb, three merge guards, run_plan dependency graph, async jobs.
  • GAP now Module claims & conflict warning: tasks/worktrees declare the paths they own (from code_map); the gateway warns when two active worktrees claim overlapping modules and shows it in worktree_list.
  • GAP next Events instead of polling: a tiny local event log (.git/break-free/events.jsonl) + bf watch / desktop notification when a worktree is blocked, hands off, or a job finishes; harness hooks (Claude hooks, Codex notify) auto-register the worktree and heartbeat at session start.
  • GAP next Cross-harness live hand-off: "continue this in Codex" — a handoff_pack that bundles task, overlay, session transcript summary and the exact command to launch the other harness in the right worktree.
  • GAP later Multi-machine: registry and overlays synced through a git ref (refs/break-free/*) or a small shared store, so a teammate's worktree on another laptop appears in your map.

Knowledge keeper

Makes what was learned findable, current and reusable.

  • DONE tasks / notes / journal / handoff / code map as Markdown, worker injection of decisions & gotchas, Obsidian-compatible, survives sessions and merges.
  • GAP now Staleness & hygiene: flag notes that reference files no longer in code_map, tasks done >30 days → archive, journal rotation, size caps; a ledger_doctor.
  • GAP next Real search: local embeddings (Ollama) over notes + journal + task outcomes; note_search becomes semantic; workers get the 5 most relevant notes for their task, not the 12 newest.
  • GAP next Decisions as ADRs with supersedes links and a generated CHANGELOG from the journal; automatic session digests (what a worker learned) proposed as notes for the lead to accept.
  • GAP later User-level knowledge: conventions that hold across all your repos (~/.config/model-gateway/knowledge/) layered under every project ledger.

Maintainer

Keeps the repo, the crew and Break Free itself healthy.

  • DONE installer with preflight/postflight, doctor (model drift, log analysis, shim, extra agents), uninstall, selftest with fake CLIs, 40 e2e tests.
  • GAP now Steward routine: a scheduled bf steward that absorbs overlays, prunes merged worktrees (proposes, doesn't delete), re-runs the verify suite on main after merges, refreshes the code map, and writes a morning brief into HANDOFF.md.
  • GAP next Repo vitals in the ledger: tests/lint/coverage/dependency freshness per commit, so "is main green?" is a ledger read.
  • GAP next Self-update & versioning: setup.mjs --update from a release, pinned versions in the answers file, migration notes; tests against the real CLIs in CI.
  • GAP later Dashboard: a local HTML view generated from ledger + registry + log — the picture on this page, live.

Cross-harness parity

Same behaviour whichever lead you open.

  • DONE one skill body for all harnesses, marker-based rules, generic MCP registration, shared ledger and registry.
  • GAP next Harness capability matrix in doctor: which harness supports hooks, skills auto-load, MCP prompts — and per-harness adapters where the rule text isn't enough (e.g. Kimi has no global instructions file).
  • GAP later Other transports: MCP over HTTP for remote/IDE harnesses (Zed, JetBrains via ACP), so the gateway can sit on one box and serve several.
